Stock Harvest AI - 要件定義書

要件定義の作成原則
- **「あったらいいな」は絶対に作らない**
- **拡張可能性のための余分な要素は一切追加しない**
- **将来の「もしかして」のための準備は禁止**
- **今、ここで必要な最小限の要素のみ**

## 1. プロジェクト概要

### 1.1 成果目標
四半期決算翌日にストップ高張り付き条件を満たす超希少銘柄を自動抽出し、月間0-2銘柄程度のプレミアムパターンを検知するAI風解析ツール

### 1.2 成功指標

#### 定量的指標
- 条件判定精度：手動計算と100%一致する結果
- 処理速度：全市場3000銘柄を30秒以内で判定完了
- 抽出結果：該当銘柄の詳細データを表形式で完全表示
- 希少性維持：月間0-3銘柄以内の超厳選抽出
- バッチ処理：15時30分以降の自動実行完了

#### 定性的指標
- 馬場さんのロジックが完全に再現されている
- 15時30分以降に自動で結果が確認できる
- 投資助言ではない「パターン検索ツール」として機能
- 「夢のAIツール」として十分なプレミアム感を演出
- 技術者以外でも結果が理解できる

## 2. システム全体像

### 2.1 主要機能一覧
- ストップ高張り付き検知機能：5つの条件による厳密フィルタリング
- 決算発表日連携機能：四半期決算翌営業日の自動判定
- 日次バッチ処理機能：15時30分以降の自動実行とレポート生成

### 2.2 ユーザーロールと権限
- 一般ユーザー：抽出結果の閲覧、過去データの確認
- 管理者：システム設定の変更、データソース管理

### 2.3 認証・認可要件
- 認証方式：基本認証なし（公開ツール）
- セキュリティレベル：公開情報のみ扱うため最小限
- 管理機能：不要（シンプルな単機能ツール）

## 3. ページ詳細仕様

### 3.1 P-001: ストップ高張り付き検索結果ページ

#### 目的
四半期決算翌日のストップ高張り付きパターン銘柄の表示と分析

#### 主要機能
- 日次自動抽出結果の表示
- 過去30日分の検索履歴表示
- 銘柄詳細情報の一覧表示
- CSV形式でのデータエクスポート

#### 必要な操作
| 操作種別 | 操作内容 | 必要な入力 | 期待される出力 |
|---------|---------|-----------|---------------|
| 取得 | 最新の抽出結果取得 | 日付指定（任意） | 該当銘柄リスト |
| 表示 | 銘柄詳細データ表示 | 銘柄コード | 株価データ・条件判定結果 |
| エクスポート | 結果データダウンロード | ファイル形式選択 | CSV/Excel形式ファイル |

#### 処理フロー
1. ユーザーがページにアクセス
2. 最新の15時30分バッチ処理結果を表示
3. 該当銘柄の詳細情報を表形式で表示
4. 必要に応じてCSVエクスポート機能を提供

### 3.2 P-002: システム設定・管理ページ

#### 目的
バッチ処理の設定確認と条件パラメータの調整

#### 主要機能
- バッチ処理ステータス確認
- 判定条件の微調整設定
- データソース接続状況確認

#### 必要な操作
| 操作種別 | 操作内容 | 必要な入力 | 期待される出力 |
|---------|---------|-----------|---------------|
| 確認 | 処理ステータス確認 | なし | 最新バッチ実行状況 |
| 更新 | 判定パラメータ調整 | 数値設定 | 更新完了通知 |
| テスト | データ取得テスト | データソース指定 | 接続結果 |

## 4. データ設計概要

### 4.1 主要エンティティ

```yaml
抽出銘柄(StockExtraction):
  概要: ストップ高張り付き条件を満たした銘柄情報
  主要属性:
    - 銘柄識別情報（コード、名称、市場）
    - 株価データ（4本値、ストップ高価格）
    - 判定結果（各条件の合否、比率計算）
  関連:
    - 決算情報(EarningsData)(1対1)
    - バッチ実行ログ(BatchLog)(多対1)

決算情報(EarningsData):
  概要: 四半期決算発表に関する情報
  主要属性:
    - 決算発表日付
    - 決算期（1Q/2Q/3Q/4Q）
    - 業績サマリー（任意）
  関連:
    - 抽出銘柄(StockExtraction)(1対1)

バッチ実行ログ(BatchLog):
  概要: 日次バッチ処理の実行記録
  主要属性:
    - 実行日時（15時30分以降）
    - 処理対象銘柄数
    - 抽出結果銘柄数
    - 実行ステータス
  関連:
    - 抽出銘柄(StockExtraction)(1対多)
```

### 4.2 エンティティ関係図
```
BatchLog ─┬─ StockExtraction ── EarningsData
          │   (1対多)           (1対1)
          │
          ├─ 実行日時
          ├─ 処理結果
          └─ エラーログ
```

### 4.3 バリデーションルール
```yaml
安値終値比率:
  - ルール: 安値 < 終値 × 0.01
  - 理由: ストップ高張り付きの厳密判定

始値終値一致:
  - ルール: 始値 = 終値 = ストップ高価格
  - 理由: 真の張り付き状態の検証

上場年数:
  - ルール: 上場日から5年未満
  - 理由: 成長株に限定した抽出
```

## 5. 制約事項

### 外部API制限
- **Yahoo Finance API**: 1日1000リクエスト制限、20分遅延データ
- **決算発表日データ**: 手動更新またはスクレイピングによる取得

### 技術的制約
- **リアルタイム処理**: 15時30分以降のバッチ処理のみ
- **データ保存期間**: 過去30日分のみ保持
- **同時アクセス**: 10ユーザー程度まで

## 6. 複合API処理(バックエンド内部処理)

### 複合処理-001: 日次ストップ高張り付き検知
**トリガー**: 15時30分の自動バッチ実行
**フロントエンドAPI**: GET /api/batch/results
**バックエンド内部処理**:
1. 全銘柄の日足データ取得（Yahoo Finance API）
2. ストップ高価格の計算（前日終値ベース）
3. 5つの条件による段階的フィルタリング
4. 決算発表日データベースとの照合
5. 抽出結果のデータベース保存
**結果**: 該当銘柄リストのJSON形式レスポンス
**外部サービス依存**: Yahoo Finance API、決算発表日DB

### 複合処理-002: 決算発表日との照合処理
**トリガー**: バッチ処理内の決算日チェック
**フロントエンドAPI**: 内部処理（直接呼び出しなし）
**バックエンド内部処理**:
1. 対象銘柄の決算発表予定日取得
2. 営業日カレンダーによる翌営業日計算
3. 処理実行日との一致チェック
4. 該当銘柄のフラグ設定
**結果**: 決算翌日フラグの設定完了
**外部サービス依存**: 決算カレンダーAPI、営業日カレンダー
